# 设计功能验收与后续路线 · v0.3

## 当前架构已冻结

- **固定 UI 层：** 播放控制、15轨卷帘、15键校对、32格逐拍谱、右下舞台。切歌时不改变布局网格；只改变内容和场景主题。
- **歌曲数据层：** `score.events` 每项记录绝对时间 `timeMs`、并行琴键数组 `notes`、`durationMs`、`velocity`、`confidence`。
- **播放时钟层：** AudioContext 高精度时钟负责调度，画面按同一 `realPosition()` 时间轴更新。角色的周期动作与逐音事件解耦，静音段冻结。
- **主题层：** `theme.id`、accent/background、snow/glow/motion、可选 `assets/stage.webp`；换曲自动加载场景。独立 `skytheme` 便于复用。
- **资产层：** `app/assets` 存放原图、场景帧、音色；原 v7 网页保存在 `legacy`，不被覆盖。

## 为什么还不能宣称“音频转谱完成”

单首电影配乐可能包含钢琴、弦乐、鼓组、人声与混响。音高检测并不等于把歌曲无损映射到15键。v0.3仅实现一个可以导出候选单旋律的入口；未来可独立增加多音分离与基于信心度的人审流程。

## 下一步的技术优先级

1. 使用 Windows 实机验证导入/导出/播放/帧动画，同时保留 console 日志和截图；尤其检查本地 HTML 文件的媒体权限。
2. 将视频识谱从单帧红色高亮检测改进为基于图像序列的动态阈值、自适应 ROI 及相邻格校准。
3. 添加多音音频转录模型独立处理服务，将其结果转为 `.skymusic` 候选谱，而不是直接修改既有曲谱。
4. 进入艺术细节阶段：第七版页面色彩、角色动画分层、光效呼吸、真实游戏装饰高清素材逐一调整。
